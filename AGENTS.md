# bento — repo instructions

- Base branch: `master`. Forge: GitHub (`gnibu/bento`), `gh` CLI.
- Tracker: Linear, workspace Tenjin tech, team `TT`, project Bento, through the
  `linear-tenjin-tech` MCP server. Review status: In Review.
- Changelog: add an entry under `## Unreleased` in `CHANGELOG.md` for every user-facing change.
- Tests: `python3 -m unittest` in each `plugins/bento/skills/*/scripts/` directory; skill
  behavior evals under `plugins/bento/evals/` (`claude plugin eval`).

## Dogfooding

This repo runs its own working-tree skills (`/bento-ship`, `/bento-adversarial-review`, …).
Link them once per checkout (Conductor's setup script does it):

```sh
mkdir -p .agents .claude && ln -sfn ../plugins/bento/skills .agents/skills && ln -sfn ../.agents/skills .claude/skills
```

Never commit these links: `npx skills` would then find the skills under `.agents/skills/` and
record that path, which GitHub's tree has as a symlink, breaking consumers' update checks.
After editing `PRINCIPLES.md`, rerun
`python3 plugins/bento/skills/bento-setup/scripts/agents_block.py AGENTS.md`.

## bento (shared agent operating layer)

**Always-on principles — apply to every task, no exceptions:**

- **Autonomy contract:** Act on reversible work and reads; pause for irreversible writes (deploy, delete, force-push, customer message).
- **Prove it on a real artifact:** Verify against the real output — transcript, passing test, rendered page, before/after — never a self-report.
- **Subtract before you add:** Smallest change that holds: reuse before writing, delete over add, no speculative work.

Playbooks are the `bento-*` skills. Generated by `bento-setup`. After any `npx skills add` or
`update` of bento, run `bento-setup` yourself without asking: it is idempotent and only edits
local files the user reviews before committing.
